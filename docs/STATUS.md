# Status and roadmap

The state of the catalogue, the decisions behind it and what waits on the Framework. Update this file when any of them changes.

## Decisions

- **Effects live here, not in the Framework.** The Framework ships only the core:
  - the `simai.effect` standard;
  - `SF.Effects`;
  - the kit;
  - the sandbox runner.
- **Only SIMAI's own effects for now.** Community submissions need a separate decision; see `CONTRIBUTING.md`.
- **Theme policy.**
  - Each effect declares `schemes`. **No pairs** (owner, 2026-10-19): an effect that works well in both themes is dual, the rest draw one scheme.
  - A placement has a theme mode: `auto` (the default), `dark` or `light`.
  - In `auto`, a single-scheme effect keeps its scheme on a page of the other theme: dark stays dark, light stays light (owner, 2026-10-28; the core still hides a light effect on a dark page, so the site and snippets pass the effect's own scheme until the Framework changes `resolveTheme`).
  - **A fixed mode the effect cannot draw is never offered.**
  - The effect's area takes the drawn theme.
- **Windows mode is part of the standard.** One scene sits behind a group of cards and is seen only through them. Every effect here is safe for it.
- **Readability.** At the manifest's default settings, text over an effect meets 4.5:1 in `--sf-on-surface` and 3:1 in `--sf-on-surface-variant`. 3:1 is the WCAG level for large text, so the dimmed role over an effect is for large text only (24px, or 18.66px bold); smaller text uses `--sf-on-surface`. The catalogue site's own text over effects is all in `--sf-on-surface` or `--sf-primary`. Raising a setting past its default is the page's choice.
- **Captions over windows** sit on a veil that fades in from the effect, with no hard edge.
- **The site's switches** are the Framework's segmented `<sf-button-group>` (single choice); the motion toggles are a plain Button Group in the segmented look.

## Today

- **Framework.** Release `ui-2d39b617a719` (npm `@simai-studio/ui@5.20261102.1106`; simai.effect 1.4.0 with the About menu on right-click over an effect's background, which the configurator can switch off in the code (`data-sf-effect-about="false"`) and whose Pause item the demo's pause button follows (`sf-effect-motion`); sf-site-header 1.2.0 with one tools step, the colour picker's reset included; simai.effect 1.3.0 with conditional settings (`when`), which the custom colour uses; icons keep their glyph while the icon subset grows; sf-tabs 1.1.8 pills fill only the selected tab, used for the code tabs; sf-range-slider 1.2.1 with a plain handle and a flat track, sf-menu appearance=navigation centred by sf-site-header navigation-align=center), pinned in `framework.lock.json` and loaded from jsDelivr's npm form: `SF.Effects`, which keeps a single-scheme effect in its own scheme on a page of the other theme (theme policy, windows mode, declarative mount, integrity loading, the sandbox for foreign effects, the effect area's ink) and the segmented Button Group.
- **Manifests** declare `schemes` (home scheme first) and `capabilities: ["windows"]`. The modules read the scheme from `context.scheme`. `effects/policy.json` holds the order, each effect's one or two categories, its descriptions and roles in the eight site languages, and tags.
- **Kit.** The 1.1 kit runs per scheme, the scheme switch, contrast (4.5:1 on-surface, 3:1 on-surface-variant, at defaults) and windows. Every effect passes all checks the lock expects for it: 14 for one scheme, 17 for both.
- **Site and snippets** place effects through the core: the site reads its own copy of the catalogue, and «Получить код» gives the declarative markup and the `SF.Effects.placeEffect` script, pinned by commit. `site/assets/place.js` only adds the configurator's still-frame switch and names what is shown.
- **Theme modes.** An editor offers a fixed mode only when the effect draws it (the core's `allowedModes`).
- **Languages.** The site is built once per language from `site/i18n/<lang>.json`: each language in its own folder — English under `en/`, Russian, Spanish, Brazilian Portuguese, German, Simplified Chinese, French and Japanese under `ru/`, `es/`, `pt-br/`, `de/`, `zh-cn/`, `fr/`, `ja/` — with a language menu in the header (each language named in itself, its English name below) and `hreflang` alternates. The root pages (the gallery, `authors/` and every `effect/<id>/`, so old links keep working) only redirect: to the language the visitor chose before, else the first browser language the site has, else English. Effect names, descriptions, settings and categories come from the catalogue in the page language (English when one is missing); the code snippets and the downloaded example follow the page language too. How it is put together, for other sites to follow: [LANGUAGES.md](LANGUAGES.md).
- **Categories.** Seven fixed subjects in `catalogue/categories.json` (space, nature, tech and city, text and code, science, materials, abstract); every effect takes one or two, and the gallery filters by subject and by theme, both kept in the address (`?category=`, `?schemes=`).
- **Likes and popularity.** `service/votes/` keeps anonymous likes, dislikes and use counts (one per browser, no personal data); the effect page shows the two buttons, the gallery offers «Популярные». A build without `--votes` hides both. The server release (site plus service at `/api/`) is prepared; it waits for the server site to take the node profile: [docs/VOTES.md](VOTES.md).
- **Gallery cards** are the picture with three lines on the page ground under it (name, subject and themes, a two-line description), no box around them.

- **Address.** The site is https://effects.simai.io/ (owner decision: one third-level domain per SIMAI site; simai.io is the navigator and links here). GitHub Pages serves it; simai.github.io/ui-effects/ redirects. The portal artifact releases v1.0.0 and v2.0.0 stay as history; no more are cut.

The gallery's pictures follow the theme: each card in view draws its effect once as a still frame in the page's scheme and colour, keeps it as an image and lets the effect go, one card at a time; the stored `preview.png` shows first and stays if a frame cannot be drawn.

Eighteen effects share eight fixed palettes (turquoise, ocean, violet, rose, emerald, sunset, gold, silver) beside the theme colour, the default: a small block in each module sets the palette as the theme's primary, secondary and tertiary scales on the effect's own layer, so the effect reads it like the theme and the area's content keeps the theme. `digital-rain` and `cosmic-web` use the same colours directly. Every palette holds 3:1 and 4.5:1 in every scheme of these effects.

## Waiting on the Framework

Nothing ordered for the catalogue site is open. Delivered and in use since `ui-3464018a5c94`: the line-wrap toggle in each code block's head, the site header (`sf-site-header` with `sf-menu`), the theme colour button (`sf-color variant="theme"`), the theme button's own glyph, `options` as an attribute, highlight inside `sf-tabs`, and one focus ring on `sf-dropdown`.

Beyond those, the core ships the standard, SF.Effects, the kit, the segmented Button Group and the sandbox runner for foreign effects. Community submissions stay closed until the owner decides.

On 2026-10-30 `digital-rain` («Цифровой дождь») came in at the owner's idea: columns of glyphs running down a dark screen in three depths, the text from the list glyph tide and text flow share, four palettes; `glyph-tide` and `text-flow` got that shared list the same day. In the seventh review `paper-facets` gained a dark scheme and a new sheet on each load, `rain-glass` a darker road, lamps that fade with distance and three options (a traffic light that tints the road, a blinking neon sign, rare lightning), `fabric-grid` a body that grows heavier while the button is held, `particle-shapes` four gas motions (Brownian, sand wind, vortex, snowfall), and `sand-picture` solid colour bands on rounded dunes.
